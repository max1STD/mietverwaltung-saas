## Tabellen-Definitionen (SQL DDL)

### 1. users
```sql
CREATE TABLE users (
  id              SERIAL PRIMARY KEY,
  email           VARCHAR(255) UNIQUE NOT NULL,
  password_hash   VARCHAR(255) NOT NULL,
  full_name        VARCHAR(100) NOT NULL,
  role             VARCHAR(20) NOT NULL DEFAULT 'vermieter', -- vermieter | mieter | admin
  totp_secret      VARCHAR(64),
  backup_codes     JSONB,
  email_code       VARCHAR(6),
  email_code_expires TIMESTAMPTZ,
  failed_login_count INT DEFAULT 0,
  locked_until      TIMESTAMPTZ,
  dsgvo_consent_at  TIMESTAMPTZ,
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  updated_at        TIMESTAMPTZ DEFAULT NOW()
);
```

## Row-Level Security (RLS)

Alle Tabellen mit `vermieter_id` bekommen RLS-Policies:

```sql
ALTER TABLE objekte ENABLE ROW LEVEL SECURITY;
CREATE POLICY objekte_isolation ON objekte
  USING (vermieter_id = current_setting('app.user_id')::INT);
-- Repeat für alle Tabellen mit vermieter_id
```

# Felder die verschlüsselt werden:
ENCRYPTED_FIELDS = {

## Was sich geändert hat (v2 → v3)

| Neu | Tabelle(n) | Warum |
|-----|-------------|-------|
| **Mieter-Historie** | `mieter_historie` | Vergangene Mieter pro WE sichtbar |
| **Einheit-Ausstattung** | `einheit_ausstattung` | Bad/Küche/Heizung/Boden pro WE speichern |
